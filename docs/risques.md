# Registre de risques

| # | Risque | Impact | Probabilité | Parade prévue | Étape |
|---|---|---|---|---|---|
| R1 | **Perte des données locales** (cache du navigateur vidé, changement de téléphone, navigation privée) | Historique de progression perdu | Moyenne | Écran « Sauvegarde » (accessible sans profil) : export complet en 1 clic (`js/backup.js`), date du dernier export affichée, rappel dans la bibliothèque si aucun export depuis 14 jours ; restauration contrôlée avec résumé et confirmation. Les modules, eux, sont dans Git : jamais perdus. | 7 ✔ |
| R2 | **JSON invalide renvoyé par le LLM** (texte autour, virgule en trop, champ manquant, clé en double) | Module inutilisable | Forte | `validate.py` extrait le JSON du texte, détecte les clés en double, donne ligne/colonne ; `--llm` produit le message de correction ; `--nettoyer` réécrit un fichier propre. | 1 |
| R3 | **Réponse fausse dans une question** (erreur de calcul ou d'énoncé du LLM) | L'enfant apprend une erreur, perd confiance | Moyenne | Le prompt impose de vérifier chaque calcul ; contrôles sémantiques (bonne réponse dans les choix, erreur fréquente ≠ bonne réponse) ; bouton « Cette question me semble fausse » qui retire la question des tirages ; signalements exportés ; correction par `merge.py` en gardant le même id. **Le parent relit un échantillon de questions avant publication.** Modules HTML : le parent essaie la page avant d'envoyer l'URL ; en cas d'erreur, on demande à Claude Code de régénérer ou corriger la page (pas de bouton « signaler », les questions sont générées). | 1, 6, 7, 9 |
| R4 | **Dépassement du quota de stockage** (≈ 5 Mo par site) | Les nouvelles réponses ne sont plus enregistrées | Faible (≈ 40 000 tentatives avant 70 %) | Événements compacts (tableaux courts) ; rappel d'export dans la bibliothèque au-delà de 70 % (estimation synchrone : caractères stockés / 5 millions) ; écriture protégée : en cas d'échec, message clair « Sauvegarde impossible, exporte tes données » plutôt qu'une perte silencieuse. | 6, 7 |
| R5 | **Dérive entre le validateur de l'app et `validate.py`** | Un module accepté par Python plante l'app, ou l'inverse | Faible | Recouvrement volontairement minimal (structure et types seulement), documenté dans `CLAUDE.md` ; test automatique (`tools/tests/test_sync.py`) qui compare `REQUIRED`, `REQUIRED_QUESTION`, `TYPES_CONNUS` et `BLOCS_CONNUS` de `js/check-module.js` au schéma. L'app écarte une question ou un bloc de leçon mal formé au lieu de planter. Normalisation des réponses : cas partagés Python/JS (`fixtures/normalisation.json`). | 2 |
| R6 | **Id modifié lors d'une correction** (le LLM renumérote les questions) | Historique d'une question détaché, doublons | Moyenne | Le prompt et le message `--llm` interdisent de changer les id ; `merge.py` remplace une question de même id, signale les énoncés quasi identiques sous un autre id et, si le LLM renvoie un module complet, les questions disparues ; il n'écrit le module que s'il est valide. | 1, 7 ✔ |
| R7 | **Contenu malveillant ou HTML dans un module** | Injection de script dans la page | Faible | Aucun `innerHTML` avec du contenu de module : rendu par `richText()` et `textContent` ; test automatique qui refuse tout `innerHTML` dans `js/` (`test_sync.py`) ; politique de sécurité (CSP) dans `index.html` qui bloque tout script ou requête hors du site ; règle dans `CLAUDE.md`. | 2 |
| R8 | **Évolution du format** (nouveau type de question, `schema_version: 2`) | Anciens modules ou outils incompatibles | Faible | `schema_version` obligatoire ; l'app refuse proprement une version inconnue ; un type = un fichier dans `js/types/`. | — |
| R9 | **Maintenance JS difficile pour un non-spécialiste** | Bug impossible à corriger seul | Faible depuis que Claude Code est le mainteneur (`CLAUDE.md`) | JS plat, petits fichiers, commentaires « pourquoi » en français, aucune dépendance ni étape de build ; asynchrone limité à la lecture de fichiers, dans `js/loader.js` (`readJson`, `readJsonFile`) ; ni worker, ni service worker, ni IndexedDB. | 2 → 7 |
| R10 | **JS généré exécuté sur le site** (modules HTML, `docs/module-html.md`) | Une page fuit des données, abîme le journal ou casse le site | Faible (contenu produit par le parent, sans tiers) | CSP obligatoire dans chaque page (`connect-src 'none'` : aucune requête possible) ; `check_html.py` refuse réseau, URL externes, accès direct au stockage, iframes ; écriture du journal uniquement par `js/suivi.js` → `addEvents()` ; `build_index.py` n'indexe que les pages conformes. Limite : une recherche de texte se contourne ; c'est un garde-fou contre les erreurs du LLM, pas contre un attaquant. | 8 ✔ |
| R11 | **Photos d'un cahier ou prénom d'un enfant publiés** (le dépôt est public) | Données personnelles en ligne, dans l'historique Git | Faible | Les photos restent dans la conversation Claude Code : le skill `/nouveau-module` interdit de les écrire dans le dépôt et ne committe que `modules/<id>.html` et `modules/index.json` ; aucun prénom réel dans une page ; `.gitignore` (`reference/*_photos/`, exports). En cas d'erreur : retirer le fichier ne suffit pas (historique), il faut réécrire l'historique. Dépôt privé envisagé puis écarté (2026-10-06) : GitHub Pages gratuit exige un dépôt public, et le site resterait public même avec GitHub Pro (seuls le code et l'historique seraient cachés). | 10 |
