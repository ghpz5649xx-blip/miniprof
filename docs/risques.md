# Registre de risques

| # | Risque | Impact | Probabilité | Parade prévue | Étape |
|---|---|---|---|---|---|
| R1 | **Perte des données locales** (cache du navigateur vidé, changement de téléphone, navigation privée) | Historique de progression perdu | Moyenne | Export complet en 1 clic, date du dernier export affichée, rappel si aucun export depuis 14 jours. Les modules, eux, sont dans Git : jamais perdus. | 7 |
| R2 | **JSON invalide renvoyé par le LLM** (texte autour, virgule en trop, champ manquant, clé en double) | Module inutilisable | Forte | `validate.py` extrait le JSON du texte, détecte les clés en double, donne ligne/colonne ; `--llm` produit le message de correction ; `--nettoyer` réécrit un fichier propre. | 1 |
| R3 | **Réponse fausse dans une question** (erreur de calcul ou d'énoncé du LLM) | L'enfant apprend une erreur, perd confiance | Moyenne | Le prompt impose de vérifier chaque calcul ; contrôles sémantiques (bonne réponse dans les choix, erreur fréquente ≠ bonne réponse) ; bouton « Cette question me semble fausse » qui retire la question des tirages ; signalements exportés ; correction par `merge.py` en gardant le même id. **Le parent relit un échantillon de questions avant publication.** | 1, 6, 7 |
| R4 | **Dépassement du quota de stockage** (≈ 5 Mo par site) | Les nouvelles réponses ne sont plus enregistrées | Faible (≈ 40 000 tentatives avant 70 %) | Événements compacts (tableaux courts) ; bandeau d'alerte à 70 % ; écriture protégée : en cas d'échec, message clair « Sauvegarde impossible, exporte tes données » plutôt qu'une perte silencieuse. | 6, 7 |
| R5 | **Dérive entre le validateur de l'app et `validate.py`** | Un module accepté par Python plante l'app, ou l'inverse | Faible | Recouvrement volontairement minimal (structure et types seulement), documenté dans `CLAUDE.md` ; test automatique qui compare la liste `REQUIRED` de `js/check-module.js` aux champs obligatoires du schéma. L'app écarte une question mal formée au lieu de planter. | 2 |
| R6 | **Id modifié lors d'une correction** (le LLM renumérote les questions) | Historique d'une question détaché, doublons | Moyenne | Le prompt et le message `--llm` interdisent de changer les id ; `merge.py` signale les questions disparues et les énoncés quasi identiques sous un autre id. | 1, 7 |
| R7 | **Contenu malveillant ou HTML dans un module** | Injection de script dans la page | Faible | Aucun `innerHTML` avec du contenu de module : rendu par `richText()` et `textContent` ; contrôle par `grep` à chaque étape ; règle dans `CLAUDE.md`. | 2 |
| R8 | **Évolution du format** (nouveau type de question, `schema_version: 2`) | Anciens modules ou outils incompatibles | Faible | `schema_version` obligatoire ; l'app refuse proprement une version inconnue ; un type = un fichier dans `js/types/`. | — |
| R9 | **Maintenance JS difficile pour un non-spécialiste** | Bug impossible à corriger seul | Moyenne | JS plat, petits fichiers, commentaires « pourquoi » en français, aucune dépendance ni étape de build, une seule fonction asynchrone. | 2 → 7 |
